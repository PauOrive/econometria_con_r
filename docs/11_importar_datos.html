4 1. Importar datos

Lo más común es que cuando trabajamos en R importemos archivos de los siguientes tipos:

  • Ficheros planos (.csv, .txt, .tsv)
  • Excel (.xls, .xlsx)
  • Bases de datos (SQL)
  • Datos de la Web (URL o a través de web API)
  • Datos geoespaciales (crear subsección!!)
  • Otros softwares estadísticos (SAS, SPSS, Stata)
  • Otros formatos (.parquet, .RData)

No siempre tendremos los datos en nuestro working directory (wd, que en R se obtiene con getwd()). Por tanto, es buena práctica definir primero la ruta y luego usarla como argumento en función correspondiente para cargar los datos.

Para definir la ruta, usamos la función file.path(), que recomiendo que se componga con una de las siguientes alternativas. Los distintos elementos van encadenados con comas dentro de la función, y no hace falta poner “/” después del elemento final de cada argumento.

4.0.0.1 Desde el home directory

  • “~” para definir el “home” directory. Alternativamente, podemos cambiar el wd con setwd(dir) al directorio de nuestro proyecto.
  • “subcarpeta1/…/carpeta_datos” especificando la ruta donde tienes los datos (idealmente dentro de una carpeta que se llame “datos” o “data”)
  • “nombre_fichero.extension”

4.0.0.2 Desde un R project (recomendada)

Para ello, deberíamos crear un .Rproj dentro de nuestro wd, de modo que luego sólo tengamos que definir la ruta especificando:

  • “carpeta_datos”
    • Lo más habitual es que editemos los scripts dentro de la carpeta scripts/. Sin menargo, las rutas relativas se toman desde el wd donde está nuestro .Rproj, por lo que no hay que definir “carpeta_datos” (los ../ es para ir un nivel de carpetas hacia atrás). En el caso de RMarkdown, conviene definir el knit directory al project directory.
  • “nombre_fichero.extension”

También es posible que la ruta sea una url tipo “https://---.extension”. La mayoría de las funciones que veremos pueden cargar estos datos directamente, siempre que la descarga no requiera autentificación.

Este proyecto está organizado con un .Rproj, de modo que las rutas siempre seran relativas.

Si se tienen muchos ficheros a cargar, para evitar definir muchos objetos ruta_fichero, otra alternativa es definir sólo la ruta a la subcarpeta y crear el file.path() con la ruta + nombre_fichero.extension directamente dentro de la función que carga los datos.

4.0.0.3 Buenas prácticas al nombrar data.frames

Cuando importamos cualquier fichero de datos en R lo asignamos a un nuevo objeto de R con <-. Está libertad para asignar el nombre que queramos es perfecta en términos de flexibilidad, pero mi recomendación es seguir ciertos criterios para poder trabajar de forma más ordenada y para que al compartir el trabajo con otras personas entiendan el código.

En otras palabras, no hagais como mi buen amigo Cristobal y llameís data1, data2, y así sucesivamente a los ficheros de datos que importais, porque a la que el número empiece a escalar es difícil recordar qué era cada cosa.

Mi recomendación es tratar de encontrar el equilibrio entre:

  • Asignar nombres específicos priorizarndo la comprensión a abreviar
  • Agregar el sufijo “datos_” o especificando el tipo de objeto:
    • “df_” si es un data.frame
    • “dt_” si es data.table
  • Usar el formato “snake case”: usar minúsculas unidas por “_”
    • esto_es_formato_snake
    • evita.este.formato
    • evitaElFormatoCamel
  • Evitar nombres demasiado largos. Algunas manipulaciones que haremos al dataset pueden ocupar pocas o muchas líneas dependiendo de cómo de largo sea el nombre, por lo que es preferible mantenerlo conciso.

Véamoslo con un ejemplo al importar los datos de incapacidad temporal.

# buen nombre
datos_it <- read_parquet("data/IT_completo.parquet")

# alternativas también buenas
datos_incapacidad_temporal <- read_parquet("data/IT_completo.parquet")
df_it <- read_parquet("data/IT_completo.parquet")

# demasiado conciso
it <- read_parquet("data/IT_completo.parquet")

# demasiado largo
datos_episodios_incapacidad_temporal <- read_parquet("data/IT_completo.parquet")

# se puede entender, pero mejor que se entienda bien a que sea conciso
datos_inca_temp <- read_parquet("data/IT_completo.parquet")

# no es necesario especificar rango temporal si sólo cargamos uno
datos_incapacidad_temporal_2015_2024 <- read_parquet("data/IT_completo.parquet")

# mejor NO usar mayúsculas, aunque realmente sean iniciales
datos_IT <- read_parquet("data/IT_completo.parquet")

4.1 1.1. Ficheros planos

Estos son ficheros de texto cuyos campos o variables están separadas siguiendo un criterio específico. Lo más habitual son coma (,) punto y coma (;) un espacio ( ) o tabulación (\t).

Las dos funciones más habituales son utils::read.table() y readr::read_delim(), con sus respectivas wrapped functions (.csv, .csv2, .delim, .delim2 y _csv, _csv2 y _tsv, respectivamente). Añado una tercera opción especialmente útil para ficheros más grandes: data.table::fread().

Normalmente elegimos la wrapped function que contiene la combinación de argumentos que se ajusta al dataset que queremos importar (la extensión más común es .csv), y únicamente definimos la ruta.

  • utils::read.table() devuelve un objeto data.frame

    • Lo más habitual es usar read.csv() que da por defecto header = TRUE, sep = “,” y dec = “.”. Para alternativas, tenemos las siguientes funciones:

      • utils::read.csv2() da por defecto sep = “;” y dec = “,”.
      • utils::read.delim() da por defecto sep = “\t” y dec = “.”
      • utils::read.delim2() da por defecto sep = “\t” y dec = “,”

  • readr::read_delim() versión más moderna del tidyverse que devuelve un objeto tibble (tbl_df, tbl y data.frame)

    • Lo más habitual es usar read_csv() que da por defecto delim = “,” y dec = “.”. Para alternativas, tenemos las siguientes funciones:

      • readr::read_csv2() da por defecto sep = “;” y dec = “,”.
      • readr::read_tsv() da por defecto sep = “\t” y dec = “.”

  • data.table::fread() versión mejorada de read.table() que devuelve un objeto data.table y data.frame. Es especialmente eficaz para ficheros grandes. Muchas de las opciones se atribuyen de forma automática, aunque también se pueden definir los argumentos explícitamente.

read.table(
  file,              #* único argumento necesario especificando la ruta
  header = TRUE,     # si la primera fila son los nombres de las columnas
  sep = "",          # qué determina la separación de los valores: "," ";" "\t" o " "
  quote = "\"",      # qué determina los str con comas: \" escapa las " 
  dec = ".",         # indicador del decimal (USA: . mientras que la UE: ,)
  fill = TRUE,       # rellena con NA si hay filas más cortas que otras
  col.names,         # por si queremos especificar colnames, con c("colname1", "...")
  colClasses,        # por si queremos especificar clase, con c("character", "...")
  ...)

read_delim(
  file,              #* argumento que especifica la ruta
  delim = NULL,      #* qué determina la separación de los valores: "," ";" "\t" o " "
  quote = "\"",      # qué determina los str con comas: \" escapa las " 
  col_names = TRUE,  # si la primera fila son colnames; si no, especificar con c("c1", ...)
  col_types = NULL,  # por si queremos especificar clase, con "cd" o c("character", ...)
  col_select = NULL, # para cargar sólo alguna de las columnas (por colname)
  skip = 0,          # número de filas que queremos no leer al inicio
  ...)

fread(
  input,              #* ya detecta si es un file, un text o un cmd de >_
  sep = "auto",       # detecta automáticamente qué determina la separación de los valores
  dec = ".",          # indicador del decimal (USA: . mientras que la UE: ,)      
  quote = "\"",       # qué determina los str con comas: \" escapa las " 
  header = "auto",    # si la primera fila son los nombres de las columnas
  colClasses,         # para especificar clase, con c("...", "...") o list(col1 = "...") 
  fill = FALSE,       # definir como TRUE si queremos rellenar con NA filas más "cortas"
  na.strings,         # para especificar qué strings deben ser interpretadas como NA
  skip = "__auto__",  # número de filas que no queremos leer al inicio
  select = NULL,      # un chr vector o una regex con patters("...")
  drop = NULL,        # un chr vector o una regex con patters("...")
  ...)

Para una descripción más detallada de alguno de los argumentos, así como ejemplos de carga de datos de IT_Sample, véase el Anexo 1.1.

4.2 1.2. Ficheros Excel

Los ficheros de Excel tienen la extensión .xls o .xlsx. A diferencia de los ficheros planos, un elemento común de los ficheros de excel es que un solo fichero contiene diversas hojas con datos tabulares.

La librería preferida en este caso es readxl, creada por Hadley Wickham, el mismo autor que readr, de modo que los argumentos son muy parecidos.

  • readxl tiene dos funciones principales muy simples:

    • excel_sheets(): para enumerar las distintas hojas que tiene un fichero excel. Retorna un chr vector con todas las hojas que tiene el fichero excel. Sólo requiere un argumento: especificar la ruta.

    • read_excel(): para cargar datos de un fichero excel. Por defecto trata de adivinar qué extensión tiene, pero si la sabemos, mejor usar directamente read_xls() o read_xlsx(). Devuelve un objeto tibble (tbl_df, tbl y data.frame).

Para una descripción más detallada de alguno de los argumentos, así como ejemplos cargando IT_Samples.xlsx, véase el Anexo 1.2..

excel_sheets(path)    #* único argumento necesario especificando la ruta

read_excel(
  path,               #* argumento que especifica la ruta
  sheet = NULL,       # qué hojas se cargan; especificar con nombre o # de la hoja
  range = NULL,       # qué hoja x filas x columnas importar (e.g. "Budget!B2:G14")
  col_names = TRUE,   # si la fila 1 son colnames; si no, especificar con c("c1", ...)
  col_types = NULL,   # por si queremos especificar clase, con c("class1", ...)
  na = "",            # qué interpretar como NA (por defecto ""; las celdas en blanco)
  skip = "__auto__",  # número de filas que queremos no leer al inicio
  n_max = Inf,        # número de filas que queremos leer en total
  ...)

# para cargar varias hojas, combinamos ambas funciones con lapply()
ruta <- "data/nombre_fichero.xlsx"

lista_hojas <- lapply(excel_sheets(ruta), # para cada hoja del Excel (arg.: sheet)
                      read_excel,         # aplica la función read_excel(file, sheet)
                      path = ruta         # al Excel que está en esta ruta (arg.: file)
                      )

# nombrar la lista permite aplicar funciones a todas a la vez (e.g. filtros)
names(lista_hojas) <- excel_sheets(ruta)

# para unir todos los df (si tienen las mismas columnas) agregando id de hoja 
tb_completo <- bind_rows(lista_hojas, .id = "hoja")

Otras librerías útiles son XLConnect y openxlsx2, que está especialmente diseñada para trabajar “back and forth” con Excel (de hecho, crea un objeto de clase “Workbook”). Es decir, para equipos/empresas que tengan todos sus datos y analisis en Excel, pero que quieran automatizar algun proceso con R. De momento no incluyo sus funciones principales aquí.

4.3 1.3. Bases de datos

Esta categoría se refiere a las bases de datos compuestas por numerosas tablas relacionadas entre sí. SQL es el lenguaje más común para programar y mantener estas bases de datos, pero hay diferencias versiones:

  • MySQL: librería RMySQL
  • PostgreQL: librería PostgreSQL
  • Oracle: librería ROracle

Pero para interactuar con la base de datos necesitamops la librería DBI; esta es la interfaz, mientras que RMySQL (o la librería correspondiente) sería la que hace la implementación.

El funcionamiento consiste en los siguientes pasos:

  1. Definir un DBIConnection object con dbConnect(MySQL(), ...) donde … incluye argumentos de autentificación que normalmente son necesarios para acceder a la base de datos. Esto crea un [My]SQLConnection object.
  2. Listamos las tablas que hay en el objeto definido con dbListTables(). Devuelve un chr vector.
  3. Leemos (alguna de) las tablas con:
    1. dbReadTable() para importar la tabla entera. Devuelve un data.frame.
    2. dbGetQuery() para importar un subset de la tabla. Devuelve un data.frame. Se emplean SQL Queries para obtener el subset de la tabla que queremos.
  4. Una vez hemos importado la tabla que queremos, deconnectamos la conexión con dbDisconnect()
dbConnect(
  RMySQL::MySQL(   # DBIdriver; connexión SQL <-> R a través de la librería correspondiente
    dbname,        #* nombre de la base de datos
    host,          #* máquina donde "vive" la base de datos
    port,          #* puerto del servidor (MySQL suele ser 3306; PostgreSQL 5432)
    user,          #* credenciales de identificación (usuario)
    password)      #* credenciales de identificación (contraseña)
)

dbListTables(conn) #* objeto de la clase DBIConnection 

dbReadTable(
  conn,            #* objeto de la clase DBIConnection
  name             # nombre de la tabla que queremos importar
)

dbGetQuery(
  conn,            #* objeto de la clase DBIConnection
  statement        #* un chr string con una SQL Query  
)

dbDisconnect(conn) #* objeto de la clase DBIConnection

En el Anexo 1.3. desarrollo funcionamiento de dbGetQuery(), incluyendo los elementos básicos de las SQL queries. No incluyo ningún ejemplo propio de importar tablas desde bases de datos puesto que no tengo nada guardado en un servidor SQL ni conozco en detalle el lenguaje.

4.4 1.4. Datos de la web

Cuando bajamos datos desde internet, por debajo de las funciones de R se producen intercambios en el lenguaje HTTP (HyperText Transfer Protocol) o, preferiblemente, HTTPS (HTTP Secure). Las opciones de formato van mucho más allá de los datos tabulares, incluyendo imagenes, ficheros ejecutables, etc. Del mismo modo, hay muchas funcionalidades que podemos programar a través de una API (Application Programming Interface), pero aquí nos centramos en la importación de datos.

Al bajarnos datos de internet podemos encontrarnos con dos alternativas:

  1. El fichero existe en una URL con una extensión. En este caso, podemos

    • descargar primero el archivo con utils::download.file() y luego leerlo desde la ruta (más común en ficheros excel). El beneficio de esta alternativa es la reproducibilidad.
    • usar directamente las funciones correspondientes a la extensión, como read_csv(), etc.
url <- "https://.../nombre_fichero.excel"
directorio_destino <- "datos"
ruta_destino <- file.path(directorio_destino, nombre_fichero.excel)
download.file(url, ruta_destino)
fichero <- read_excel(ruta_destino)

  1. Hay que interactuar con una web API para obtener los datos. Es decir, una interfaz para importar o añadir datos a un servidor mediante verbos de HTTP. Existen varias librerías que sirven este propósito:

    • httr para obtener responses y descargar datos
    • jsonlite para interpretarlos (si tienen el formato JSON) y convertirlos en objetos R manejables (listas, data.frames, etc.).

Al interactuar con una API, los pasos más comunes son los siguientes:

  1. definimos un httr::GET() request, que devuelve un response object, que contiene la siguiente información:
    • status code: indica si la llamada es exitosa (200) o no (40x)…
    • content-type: qué formato tiene el fichero
    • size: cómo de pesado es el archivo
  2. Si la llamada es exitosa, podemos acceder al contenido con la función httr:content(). Por defecto, ya interpreta con qué formato importar los datos (csv, texto, JSON, etc.), pero se pueden importar sin formato definiendo as = "raw". Dependiendo del contenido, devuelve un chr vector, named list, etc.
  3. Usamos jsonlite::fromJSON() para convertir el contenido a un formato conveniente para su manejo en R. De hecho, esta función puede usarse directamente para obtener URLs.
url <- "http://www.ejemplo.com"
resp <- httr::GET(url)           # devuelve un response object
resp                             # imprimimos para verificar status, type y size.
content <- content(resp)         # para acceder al contenido del response object
list <- fromJSON(content)        # para convertir el JSON en un data.frame

Las APIs acostumbran a almacenar datos en formato XML o JSON (más moderno). En el Anexo 1.4. desarrollo la estructura básica de JSON y algunas de las funciones de jsonlite.

4.5 1.5. Otros softwares estadísticos

A pesar de que cada vez se usan menos en pro de R, python o julia, aún hay quien prefiere usar los softwares estadísticos más antiguos para sus análisis, que tienen su propia extensión para guardar ficheros de datos.

Hay dos librerías princpales para importar este tipo de datos:

  • haven más moderna y rápido, pero suporta menos tipos de ficheros (aunque incluye los de SAS, STATA y SPSS). Devuelve un objeto tibble (tbl_df, tbl y data.frame). Los argumentos son muy similares a los de la librería readr.

  • foreign del R Core Team, más antigua pero soporta más clases de ficheros. Por ejemplo, no puede cargar .sas7bdat directamente, sólo “librerías SAS” (.xport), y no puede cargar ficheros .dta de versiones posteriores a Stata 12. Sin embargo, da más control sobre la importación, único frente en el que puede ser más útil que haven.

Los softwares más comunes y funciones de cada una de estas librerías para importarlos son las siguientes:

Software Nombre Ámbitos de uso Extensión haven foreign
SAS Statistical Analysis Software business analytics, bioestadística, ciencias médicas .sas7bdat .sas7bcat read_sas()
STATA STAtistics and daTA economía .dta read_stata() read_dta() read.dta()
SPSS Statistical Package for Social Sciences ciencias sociales .sav .por read_spss() read_sav() read_por() read.spss()

Sin embargo, otras variables están “etiquetadas” (labelled), lo que puede traer problemas. Véase el Anexo 1.5. para saber cómo solucionarlo, con el ejemplo de IT_Sample.dta.

4.6 1.6. Otros formatos

Por último, pero no menos importante, de entre el resto de formatos de ficheros de datos que existen, considero esencial incluir en esta guía los ficheros .parquet y los ficheros .RData. Ambos son formatos binarios, por lo que son muy útiles para datasets grandes. Sin embargo, R está sólo pensado para guardar objetos de R, mientras que parquet es interoperable, aunque sólo

  • Los ficheros .parquet forman parte del ecosistema Apache y son la opción favorita cuando trabajemos con datasets muy grandes. No sólo permiten guardarlos de forma muy compacta, sino que además se pueden cargar directamente sólo un subset de columnas. La librería para ello es arrow

    • En algunas funciones como read_delim() también hay argumentos similares, pero realmente R carga el dataset y luego se queda sólo con las seleccionadas (read_parquet() hace lo mismo si definimos mmap = FALSE).

    • Podemos usar tanto un vector de colnames como una expresión de selección “tidy”.

  • Los ficheros .RData o .rds realmente no son muy comunes porque sólo viven en el ecosistema de R. Concretamente,

    • Los ficheros .RData pero pueden ser muy útiles puesto que guardan todos los objetos de una sesión de R (no sólo los datasets, sino cualquier objeto de R). Esto es útil cuando dejamos una sesión de trabajo a medias y queremos continuar donde nos habíamos quedado sin necesidad de correr todo el código de nuevo. Al cargarlos, mantienen los nombres que tenían en la otra sesión.

    • Los ficheros .rds sirven para guardar un sólo objeto de R. Al cargarlos, podemos redefinir el nombre asignandolo a una variable nueva.

read_parquet(
  file,                    #* ruta al fichero .parquet     
  col_select = NULL,       # para cargar sólo un subset de columnas
  as_data_frame = TRUE,    # por defecto carga un tibble, if FALSE carga un Arrow Table
  mmap = TRUE,             # para leer en RAM sólo las columnas especificadas.
  ...
)

load(file)                 #* ruta al fichero .RData
 
readRDS(file)              #* ruta al fichero .rds
